Claude Code 在 TUN 模式下为何还活不过 1 个月？

2026-04-15 · 约 3 分钟读完 · X 301K 阅读
Claude Code TUN 模式 账号安全 网络

我用Claude Code一个下午烧完extra credit 200刀，然后账号没了。

当天晚上打开终端，提示登不上去。

我盯着屏幕愣了大概五秒，脑子里第一个反应是：密码输错了？

没有。账号真的没了。

Anthropic白送的200刀，我那天下午把它烧完了，觉得很划算——然后当晚账号就没了。后来反复复盘，才想清楚自己到底做错了什么。说出来，因为我见过太多人在重复同样的路径。

第一个问题，几乎所有人都没意识到

开了 Clash 的 TUN 模式，你以为自己走代理了。

没有。

你用环境变量或者TUN 模式？有时候不稳。Claude Code 兜底读 ~/.claude/settings.json 里的代理配置。这个文件，大多数人从来没碰过，因为根本不知道它的存在。

结果是：你看着代理软件开着，绿灯亮着，但 Claude Code 发出去的每一条请求，走的都是你的国内IP。

你要在 ~/.claude/settings.json 里手动加这个，或者让ai帮你加：

"env": {
    "HTTP_PROXY": "http://127.0.0.1:7897",
    "HTTPS_PROXY": "http://127.0.0.1:7897"
  }

端口换成你本地代理的监听端口（Clash 默认7897）。

加完之后，不要假设它有效——重启 Claude Code，在Clash network里检查一下。这步不验证，你可能自始至终都在裸奔，自己不知道。关键字：claude，athropic

还有一个更不直觉的地方：注册那一刻用的IP，比你日常用的IP重要得多。

Anthropic 这东西不告诉你，也不解释。但从大量案例来看规律很清楚：

用住宅IP或海外静态IP注册 → 账号开局分高，容错空间大

用数据中心IP注册 → 分低一点，但还能跑

日常用哪个节点，Anthropic 有一定容忍度，偶尔切了也不会立刻出事。

那200刀是怎么把账号送走的

我后来把封号路径复盘出来了，逻辑清晰得让我有点沮丧。

可以用一个心智模型来理解：信用积分 + 斩杀线 + 引爆点。

每个账号都有一个看不见的信用积分。账号越老、行为越正常，积分越高。高积分账号有更高的容错空间，低积分账号几乎没有缓冲。

这就解释了为什么同样的操作，老号没事，新号直接没了。

斩杀线是用量维度的异常阈值：短时间内消耗过多额度，账号会被标记进高风险状态，进入重点监控。单独触发斩杀线不一定立刻封，但你从普通账号变成了随时可以被引爆的状态。

我那天：一个下午烧完200刀 → 触发斩杀线 → 进入高风险 → 国内IP踩中引爆点 → 当晚封号。

每一步都对得上。

国内IP/香港IP就是最典型的引爆点。Anthropic在中国没有合规业务，大陆IP本身是个强风险信号，在高风险状态下就是最后一根稻草。

怎么避免：

不要在短时间内集中烧额度，哪怕你有正当需求。你的用量模式不能看起来像API中转站——高频、大量、规律的调用是红旗。

触发了5小时速率限制？尽量慢一些，尽量留5%。

按七天周期管理用量，重制前务必留5%。

明确禁止的几件事

这几条不要踩：

禁止用 openclaw 小龙虾，禁止授权到第三方应用。

禁止任何形式的反代中转——专号专用。

你有没有遇到过账号莫名其妙就没了？十有八九是上面这些原因之一。

  • Tun模式不够，还需要在settings里设置代理：有时候网络开关，机器重启，可能都会让 Tun 临时失效
  • 不用大陆和香港节点
  • 新号注册ip更重要
  • 注意养号，不滥用，钓鱼的extra credit不要上钩
  • 注意支付方式

说说你是哪个环节出的问题——留言，我可能踩过同款。

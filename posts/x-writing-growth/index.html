一文看懂怎么在 X 持续写作涨粉

2026-04-29 · 约 7 分钟读完 · X 60K 阅读
X 写作 涨粉 内容创作

你有没有好奇过，为什么有些博主能源源不断输出爆文？他们每周都能稳定产出几篇看起来就想转发的稿子，节奏完全不像人能维持的。

我深度调研了8个博主，结合我自身的经验，总结了本文，共同点不是天赋，是流程。

我没买流量、没团队、没素材库。把写作当一个工程问题，拆成了一套可重复的流程：熟悉领域、定受众、看平台、立人设、写完等一等、再看数据复盘。

每一步都不大，但每一步都能让一篇稿子的成功率提升一点。

新人照着跑，老博主拿来对一遍——尤其是那种发了一年、越发越没人看、开始怀疑自己是不是天生不适合的那种。

这篇你会拿到什么

写作不难，分为三段方法，外加一个你今天就能跑的skill：

  1. 写作第一步，选题 + 受众，要为 99% 的读者写
  2. 写作第二步，平台逻辑决定写法
  3. 写作第三步，别马上发，润色（把我后悔率从 1/3 降到 0）
  4. 动手清单：一个skill打包带走，没时间读的可以直接跳到这里

读完不会一夜爆款。会有一套越跑越顺的流程。

爆款是流程跑顺之后的副产品。

一、写作第一步，选题 + 受众

写一篇稿子之前，有两件事必须先想清楚：写什么（选题），写给谁看（受众）。

1.1 选题：从你的爱好和工作里挖

最稳的选题不是去追热点，是去找你已经在做的事。

我发的每一条都来自三个池子：

  1. 池子 1：我每天的工作（写代码、做 AI 项目、踩的坑）
  2. 池子 2：我的爱好（折腾设备、买东西、群里吹牛逼、散步）
  3. 池子 3：我跟人聊出来的，朋友的真实问题

为什么必须从这三个池子里挖？只有这些题目你能持续输出。

热点会变化，你的兴趣不会。

一个题目今天能写、半年后还能补充、明年看回去还有新角度，可持续选题。

光从兴趣里挖还不够，还得让 X 的算法帮你推——方法是结合热点叠进去：

  1. 热点关键词：claude、agent、ai、gpt等等
  2. 你的人设方向：实战、AI博主、健康博主、心灵导师
  3. 你的真实经历：我又发现了一个 AI 小技巧、我朋友有个表哥挂了( 狗头)

同一个热点，别人用一行字蹭，你用人设+真实经历+选题池子来蹭，效果完全不一样。

1.2 搞清楚你的读者是谁

这一步 90% 的人会跳过——直接开始写。然后发现自己的稿子谁都不想读。

我自己每发一篇之前都会想一想这几个题。

Q1：你想吸引同频的人，还是不同维度的人，他们想获得什么？

我自己的例子。我做 AI 工程相关的工作。我学到的 AI 技术、跑过的工具栈，在 X 上保守估计排前 1%——吹了点牛逼。

如果我每篇都为这前 1% 写——讲底层、讲源码、讲推理优化——读者池子小到爆款都够呛。

真正能让我们破圈的，是另外那 99%——对 AI 感兴趣、但还没把 AI 用顺、想看真人怎么实操、希望降低自己学习成本的那 99%。

用前 1% 的技术认知，写给 99% 的好奇者看。

Q2：你扮演什么角色？

对我来说，最后只有坦诚型走通了。那条把我喷醒的评论我现在都记得原话：

"实践哥？你这个东西还没有实践过，叫个毛的实践哥瞎评论？"

我盯着屏幕看了很久。气过、想反驳过、想骂回去过。后来我做了一件事： 把那个评论删了——确实没实操，写得心虚。

说实话当时还是气了挺久的。后来想想，这是负反馈，比正反馈还重要。

从那篇开始，选题真的变了。

二、写作第二步，平台逻辑决定写法

选题和受众定好之后，开始动笔。

X 上没有读者，只有路过的人。

我有个朋友，公众号能写 10 万+。她兴冲冲把同一篇原文搬到 X，一共 7 个转发——其中 5 个还是她自己的小号点的，一个是我帮她转的。

她以为是粉丝池没起来。我跟她分析了一下，平台底层的传播机制根本不一样，X 主要靠转发和二次扩散：

我每周复盘看三件事：

  • 爆的稿：哪几篇阅读 / 转发明显高于平均？爆的那条共性是什么？
  • 沉的稿：哪几篇明显低？是题目错了还是写法错了？
  • 用户画像：来读我的人有没有变化？

每一条都很关键，要面向读者写作、面向移动端，最后那条 76.4% 是这套流程里最关键的反馈。

三、写作第三步，别马上发，润色

写完一篇稿子，不要立刻发。

这是这套流程里最反直觉的一条，也是我觉得最有用的。

新作初期，经常犯的错误时写完就发，那1小时我以为那篇会破100。

我有个硬标准：

写完至少放 2小时，最好一觉，散个步

之前我发出去后悔率大概每 3 篇有 1 篇，加了2小时之后接近 0。

正确的做法很简单：

写完  → 关掉文件
       → 散步 / 吃饭 / 睡一觉 / 第二天早上再看
       → 重读，这次你是用读者的视角
       → 几乎一定会发现：开头啰嗦了 / 中间例子不够具体 / 结尾收太硬
       → 改一版
       → 再等一会儿
       → 再改一版

为什么必须等？

这个习惯我类比成AI的上下文影响，LLM 在 context 里搞不清谁好谁差，你也一样。

你刚写完的稿子也一样：脑子还热着，所有的语义、所有的脉络都跟稿子绑在一起，你读它的时候是在"补全"，不是在"评判"。

给自己一段"clear context"的时间，是写作里最便宜的杠杆。

读者读到的是你的第二版或第三版。你写完就发，读者读到的是你的第一版，一个连明天的自己都还没认可的版本。

忍住马上发射。

四、一个 skill 打包带走

每篇发稿前，确定三件事情：

  1. 定角色——一句话："我是那个 __ 型博主"，半年别换
  2. 找受益人——"谁会因这篇受益"，答不出具体一类人就重写
  3. 冷一冷——至少放 2 小时，让读者读到的是第二/三版

90% 的博主连这 3 件都没做齐，所以爆了不知道为啥爆，沉了不知道为啥沉。

手动过容易偷懒。把下面这段丢进 Claude / Codex/ DeepSeek，创建一个适合自己的skill，每次写完丢给它跑一遍：

你跟我探讨一下创建下面的 skill，先探讨挖掘我的需求：

你是我的审稿助手。我把草稿丢给你，你给我提供建议，你习惯用启发式的方式帮我决策，一次一个问题。
第一次你会帮我设定persona
 我的人设「我是那个 __ 型博主」（我会单独告诉你）。
 判断语气、立场、用词是否符合。指出具体句子并给改写建议。
先确定平台，例如推特长文（类似公众号长文）、推特 thread、公众号长文、小红书

【审稿要素1：受益人】
 反问我："谁会因这篇具体受益？"
 具体一类人（如"对AI感兴趣的小白、X博主"），
 根据我给的一些笼统提示和我的文章，可以进行编写。

【审稿要素2：冷读】
 假装是第一次刷到的陌生人（受益人人设），标出 3 处最可能让你划走的位置，使用sub agent来跑避免上下文污染：
 开头是否啰嗦、例子是否不具体、结尾是否收硬。
 每处给"原文 → 改法"对照。

用法：写完 →丢进 skill → 改一版 → 等 2 小时或睡一觉润色一下 → 再发。

说实话，大多数人卡的不是选题也不是写法。

最后介绍一个工具

这段开始恰饭。

Skill做完后，审稿这种活其实没必要用旗舰模型。每次审稿会用单独上下文很贵，所以我用Claude创建完skill，再用 Claudian + Ling-2.6-1T 审稿的，在同级别模型里属于 SOTA，目前最好的水平。它的设计初衷就是给"读文档 + 调脚本 + 跑循环"这种 agent 工作流用的，定位特别贴合本文场景。

我跑了一周，最直观的一个感受：写长稿不会写到一半逻辑跑偏——对做长内容的博主非常适合，又便宜又好。

通过 Novita Labs 在 OpenRouter 上线，还有一周免费试用。要试就趁现在。

最后，评论区告诉我，你卡的是选题，还是写法？还是卡最后没发出去?

所以先选一个，扔评论区，哪怕理由很蠢。

A. 选题选不出来

B. 发了一年，涨粉速度比我长白头发还慢

C. 写完了不敢发

D. 每次发完就后悔，总觉得没写到点
